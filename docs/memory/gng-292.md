#292 (2026-11-23, branch `292-ghosts-n-goblins-ram`). Ghosts'n Goblins' RAM is identical to MAME on 3,000 frames with and without input. Three generic fixes:

1. **`set_periodic_int` is a real timer.** The compiler emits one frame event with `frequency` and `periodAttoseconds` (`attotimePeriodAttoseconds` in src/kg/build.ts: integral `from_hz` divides in integers, XTAL rates in doubles, `from_ticks` is ticks × truncated period). The frame runner (`periodicEvents`, `firePeriodic`) keeps an exact `next` expiry, lowers the round's target to it, and fires at the head of the next round. No fixed lines, no per-line carry, and a periodic event no longer forces `perLineSchedule`. A RESET release re-arms it a period from the release (`rearmPeriodic`, MAME `interface_post_reset`).
2. **devcb `set_inputline` synchronizes** (`cpuLine` in `effectBindings`), as driver-code `set_input_line` already did. `busreq`/`core` lines are still applied in place.
3. **`set_output_gain` with an unchanged gain updates nothing** (src/hardware/speaker/runtime.ts), as `sound_stream::set_output_gain` returns early. Taito SJ's `bankswitch_w` sets every gain per bank switch from the main CPU; per-line rounds hid it.

**The non-obvious part:** round length changes cycle counts even with no handshake. MAME's `timeslice` counts cycles with `divu_64x32(delta >> m_divshift, m_divisor)`, which over-counts a little as rounds lengthen (the 6809's 666,666,666,666 as cycle needs divshift 8). Over a 4,224-cycle round the 6809 got the cycle straddling VBLANK; MAME's 151-cycle round after the fourth 240 Hz expiry did not. So a missing round end shows up as a one-cycle skew on a processor that never talks to the timer's owner.

**How it was found:** `diverge` showed no latch traffic. Tapping one RAM byte from frame 1 (`against --io maincpu:1697-1697:rw --io-frames 1-89 --keep`) showed a constant one-cycle lag; tapping `maincpu:0-ffff:rw` for frames 1-6 and diffing the kept `mame-io.txt`/`ours-io.txt` put it at the first frame boundary (a 6809 in `SYNC`). Then dist-side logging in generated-frame.js showed the round lengths.

**Results (`compare --against main`, 8 periodic boards):** RAM identical for gng, asteroid, congo, gunsmoke, spyhunt; junglek first differs 2 → 364; bzone 209 as before; elevator unchanged (80 bytes at frame 2). `--against main` runs main's runtime over this tree's dist, so boards that used fixed lines on main ran on the carry there: its "before" isn't true main for them.
